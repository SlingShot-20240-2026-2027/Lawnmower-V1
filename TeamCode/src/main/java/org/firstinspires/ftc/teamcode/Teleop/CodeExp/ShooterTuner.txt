SHOOTER TUNER + SHOOTERNF - TUNING GUIDE
OpMode: "Shooter Tuner" (group Tuning)
Subsystem: Subsystems/Shooternf.java  (flywheel + hood, Ivy command-based)

======================================================================
1. SETUP
======================================================================

1. Connect a laptop to the robot's Wi-Fi and open FTC Dashboard:
   http://192.168.43.1:8080/dash
2. On the Driver Hub run "Shooter Tuner" (INIT, then PLAY).
3. In Dashboard:
   - Configuration tab: open "Shooternf" (all gains, target RPM, hood) and
     "ShooterTuner" (step test, feed options). Changes apply instantly,
     no rebuild needed.
   - Graph tab: plot targetRpm and rpm together. Add error and power on a
     second graph if you want.

Config names: shooterleft, shooterright (motors), hood1 (servo), plus
intake, intakeColor, transfer for feeding.

======================================================================
2. GAMEPAD 1
======================================================================

  A ............ shooter.on()  (spin to TARGET_RPM)
  B ............ shooter.idle() (power off, also stops the step test)
  RT (hold) .... transfer runs while held, idle when released
  Intake ....... runs the whole time from PLAY to STOP (no button)
  Y ............ step test on/off (see 4)

======================================================================
3. THE CONTROLLER
======================================================================

  power = (kV * target + kS + kP * error + kI * integral - kD * dRpm/dt)
          * (12 V / battery V)

  kV   feedforward: power needed per RPM. Does most of the work.
  kS   static friction: small constant power added when spinning.
  kP   corrects the remaining error and recovers speed after a shot.
  kI   removes a small steady error that is left over. Only active
       within I_ZONE_RPM of target, capped at INTEGRAL_MAX_POWER.
  kD   damps overshoot. Uses the change in RPM, so it doesn't kick when
       the target changes.

Voltage compensation keeps shots the same on a full or tired battery.
VELOCITY_FILTER: 1.0 = raw encoder speed, lower (0.3-0.6) = smoother
but slower reading. Keep 1.0 unless the rpm line is very noisy.

READY = within READY_TOLERANCE_RPM (50) for READY_HOLD_MS (80 ms).

======================================================================
4. TUNING STEPS (do them in this order)
======================================================================

Set kP, kI, kD, kS to 0 first.

STEP 1 - CHECK DIRECTION
  Press A with TARGET_RPM 2000. Both flywheel wheels must spin the
  shooting direction and rpm must be POSITIVE.
  - Wrong spin direction: flip LEFT_REVERSED / RIGHT_REVERSED.
  - rpm negative: set ENCODER_SIGN = -1.
  - rpm 0: check ENCODER_MOTOR_NAME is the motor with the encoder cable.

STEP 2 - kV (feedforward)
  Start kV = 1 / (motor free speed RPM). Bare 6000 RPM motor: 0.000167.
  Try TARGET_RPM 2000, then 3500. Raise kV if rpm settles under target,
  lower it if over. Goal: within ~2-3% at every speed WITH kP = 0.
  If low speeds are short but high speeds are right, add a little kS
  (0.02-0.05) and lower kV slightly.

STEP 3 - kP (recovery)
  Turn on the step test (Y, or STEP_TEST in Dashboard). It switches
  between STEP_LOW_RPM and STEP_HIGH_RPM every STEP_PERIOD_MS.
  Raise kP (start 0.0002, then 0.0005, 0.001...) until rpm reaches each
  new target quickly. Stop raising when rpm starts to overshoot or wobble,
  then back off ~20%.

STEP 4 - kD (only if overshoot)
  If rpm overshoots after a step, add kD in small amounts (0.00001 and
  up) until it settles cleanly. Too much makes the rpm line jittery.

STEP 5 - kI (only if a steady error remains)
  If rpm sits a little off target for a long time, add kI (0.0001 and
  up). Too much causes slow wobble.

STEP 6 - SHOT RECOVERY
  Turn the step test off. Spin up (A), load pollen (the intake is always
  running), then hold RT to run the transfer and shoot.
  Watch "Last shot drop (rpm)" and "Last recovery (ms)". Raise kP to
  recover faster. Turn on FEED_ONLY_WHEN_READY to see how fast you can
  shoot back-to-back with every shot at speed.

STEP 7 - SHOOTER VELOCITY + HOOD PER DISTANCE
  Place the robot at a shooting distance. Adjust TARGET_RPM (D-pad) and
  HOOD_POSITION (bumpers) until shots go in reliably. Write down
  distance, RPM, hood. Repeat at several distances; those numbers go in
  the lookup table or your auto's shooter.on(rpm, hood) calls.

STEP 8 - SAVE
  Dashboard changes are LOST when the robot restarts. Copy the final
  values into the public static fields at the top of Shooternf.java
  and rebuild.

======================================================================
5. USING SHOOTERNF IN AUTONOMOUS / TELEOP (Ivy)
======================================================================

  Scheduler.reset();
  Shooternf shooter = new Shooternf(hardwareMap);
  waitForStart();
  schedule(shooter.periodic());     // runs the PIDF every loop - REQUIRED
  schedule(sequential(
          shooter.on(),             // or shooter.on(3200, 0.45)
          shooter.waitUntilReady(),
          ...feed commands...,
          shooter.idle()
  ));
  while (opModeIsActive()) {
      Scheduler.execute();
  }

  - shooter.on()                 spin to TARGET_RPM / HOOD_POSITION
  - shooter.on(rpm, hood)        spin to a given rpm and hood
  - shooter.idle()               power off
  - shooter.waitUntilReady()     finishes when at speed
  - shooter.periodic()           background loop; schedule once. It has
                                 no requirement, so on()/idle() never
                                 cancel it. When it is cancelled (or the
                                 Scheduler is reset), the flywheel stops.
  - Without Ivy: call shooter.update() every loop instead of periodic().
