SHOOTER TUNER + SHOOTERNF - TUNING GUIDE
OpMode: "Shooter Tuner" (group Tuning)
Subsystem: Subsystems/Shooternf.java  (flywheel + hood, Ivy command-based)
Speed control: setVelocity() - the Control Hub runs the velocity PIDF on
BOTH flywheel motors, each with its own encoder.

======================================================================
1. SETUP
======================================================================

1. Connect a laptop to the robot's Wi-Fi and open FTC Dashboard:
   http://192.168.43.1:8080/dash
2. On the Driver Hub run "Shooter Tuner" (INIT, then PLAY).
3. In Dashboard:
   - Configuration tab: open "Shooternf" (gains, TARGET_RPM, HOOD_POSITION)
     and "ShooterTuner" (step test, feed options). Changes apply
     instantly, no rebuild needed. New gains are sent to the hub the
     next loop.
   - Graph tab: plot targetRpm, rpm, leftRpm, rightRpm together. Put
     error and currentAmps on a second graph if you want.

Config names: shooterleft, shooterright (motors, BOTH need encoder
cables), hood1 (servo), plus intake, intakeColor, transfer for feeding.

======================================================================
2. GAMEPAD 1
======================================================================

  A ............ shooter.on()  (spin to TARGET_RPM)
  B ............ shooter.idle() (coast to a stop, also stops step test)
  RT (hold) .... transfer runs while held, idle when released
  Intake ....... runs the whole time from PLAY to STOP (no button)
  Y ............ step test on/off (see 4)
  TARGET_RPM and HOOD_POSITION are changed in Dashboard only.

======================================================================
3. THE CONTROLLER
======================================================================

  Each motor: setVelocity(target ticks/s) with
  setVelocityPIDFCoefficients(kP, kI, kD, kF * 12 V / battery V)

  Units are the hub's own (ticks per second, output scale 32767), so the
  numbers are much bigger than setPower-style gains.

  kF   feedforward. Does most of the work. kF = 32767 / max ticks/s.
       Bare 6000 RPM motor, 28 ticks/rev: 32767 / 2800 = 11.7 (default).
  kP   corrects the remaining error and recovers speed after a shot.
       Start around 0.1 * kF (1.2 default).
  kI   removes a small steady error. Start around 0.1 * kP (0.12).
  kD   damps overshoot. Usually 0.

  VOLTAGE_COMPENSATION raises kF as the battery drops so shots stay the
  same on a full or tired battery. kF is re-sent when it changes > 1%.
  "kF sent" in telemetry is the value the hub is using right now.

  IDLE: the motors are switched off the velocity loop and coast (no
  braking), the same as before.

  rpm = average of leftRpm and rightRpm. VELOCITY_FILTER only smooths
  this reading (telemetry / READY); the hub loops use the raw encoders.
  READY = within READY_TOLERANCE_RPM (50) for READY_HOLD_MS (80 ms).

======================================================================
4. TUNING STEPS (do them in this order)
======================================================================

Set kP, kI, kD to 0 first. Leave kF at 11.7.

STEP 1 - CHECK DIRECTION AND BOTH ENCODERS
  Press A with TARGET_RPM 1500. Both wheels must spin the shooting
  direction and leftRpm AND rightRpm must both be POSITIVE and close.
  - Wrong spin direction: flip LEFT_REVERSED / RIGHT_REVERSED.
  - One side negative: flip that side's *_REVERSED (motor and its
    encoder are reversed together) and check the wheel still spins the
    right way. If it doesn't, the encoder cable or motor wiring is
    swapped/reversed on the robot.
  - One side 0 or wildly fast: that encoder is not reading. PRESS B
    NOW - a motor with no encoder runs at full power under setVelocity.
    Fix the cable before going on.

STEP 2 - kF (feedforward)
  Try TARGET_RPM 2000, then 3500, with kP = kI = 0. Raise kF if rpm
  settles under target, lower it if over. Goal: within ~2-3% at every
  speed. Small steps (0.3-0.5 at a time).

STEP 3 - kP (recovery)
  Turn on the step test (Y, or STEP_TEST in Dashboard). It switches
  between STEP_LOW_RPM and STEP_HIGH_RPM every STEP_PERIOD_MS.
  Raise kP (1, 2, 4, 6...) until rpm reaches each new target quickly.
  Stop when it overshoots or wobbles, then back off ~20%.

STEP 4 - kI (only if a steady error remains)
  If rpm sits a little off target, add kI (0.1 and up). Too much
  causes slow wobble / overshoot.

STEP 5 - kD (only if overshoot)
  Add kD in small amounts (0.5 and up) until it settles cleanly. Too
  much makes the rpm line jittery.

STEP 6 - SHOT RECOVERY
  Turn the step test off. Spin up (A), load pollen (the intake is always
  running), then hold RT to run the transfer and shoot.
  Watch "Last shot drop (rpm)" and "Last recovery (ms)". Raise kP to
  recover faster. Turn on FEED_ONLY_WHEN_READY to see how fast you can
  shoot back-to-back with every shot at speed. leftRpm and rightRpm
  should drop and recover together.

STEP 7 - SHOOTER VELOCITY + HOOD PER DISTANCE
  Place the robot at a shooting distance. Adjust TARGET_RPM and
  HOOD_POSITION in Dashboard until shots go in reliably. Write down
  distance, RPM, hood. Those go into CLOSE_* / FAR_* in the teleops and
  into your auto's shooter.on(rpm, hood) calls.

STEP 8 - SAVE
  Dashboard changes are LOST when the robot restarts. Copy the final
  values into the public static fields at the top of Shooternf.java
  and rebuild.

======================================================================
5. USING SHOOTERNF IN AUTONOMOUS / TELEOP (Ivy)
======================================================================

  Scheduler.reset();
  Shooternf shooter = new Shooternf(hardwareMap);
  waitForStart();
  schedule(shooter.periodic());     // runs the speed control every loop - REQUIRED
  schedule(sequential(
          shooter.on(),             // or shooter.on(3200, 0.45)
          shooter.waitUntilReady(),
          ...feed commands...,
          shooter.idle()
  ));
  while (opModeIsActive()) {
      Scheduler.execute();
  }

  - shooter.on()                 spin to TARGET_RPM / HOOD_POSITION
  - shooter.on(rpm, hood)        spin to a given rpm and hood
  - shooter.idle()               coast to a stop
  - shooter.waitUntilReady()     finishes when at speed
  - shooter.waitUntilReady(ms)   same, gives up after ms
  - shooter.periodic()           background loop; schedule once. It has
                                 no requirement, so on()/idle() never
                                 cancel it. When it is cancelled (or the
                                 Scheduler is reset), the flywheel stops.
  - Without Ivy: call shooter.update() every loop instead of periodic().

  The commands are the same as the setPower version, so the teleops and
  SoloAuto1Tip did not change.
package org.firstinspires.ftc.teamcode.Auton.pedro;

import com.pedropathing.api.Paths;

import com.pedropathing.api.PoseFactory;
import com.pedropathing.follower.Follower;
import com.pedropathing.math.Pose;
import com.pedropathing.paths.Path;
import com.pedropathing.ivy.Command;
import com.pedropathing.ivy.Scheduler;
import static com.pedropathing.ivy.Scheduler.schedule;
import static com.pedropathing.ivy.commands.Commands.*;
import static com.pedropathing.ivy.groups.Groups.parallel;
import static com.pedropathing.ivy.groups.Groups.sequential;
import static com.pedropathing.ivy.pedro.PedroCommands.follow;
import com.qualcomm.robotcore.eventloop.opmode.Autonomous;
import com.qualcomm.robotcore.eventloop.opmode.LinearOpMode;

import org.firstinspires.ftc.teamcode.Subsystems.Intake;
import org.firstinspires.ftc.teamcode.Subsystems.Shooternf;
import org.firstinspires.ftc.teamcode.Subsystems.Transfer;
import org.firstinspires.ftc.teamcode.Subsystems.DeployRamp;


@Autonomous(name = "DuoAuto2Tip", group = "Autonomous")
public class DuoAuto2Tip extends LinearOpMode {

    private Follower follower;
    private Shooternf shooter;
    private Transfer transfer;
    private Intake intake;
    private DeployRamp ramp;

    private final PoseFactory poseFactory = PoseFactory.degrees();

    private final Pose start = poseFactory.of(55.9698, 9.1683, 90);
    private final Pose move1 = poseFactory.of(9.5662, 9.6402, -92.5584);
    private final Pose move1Control1 = poseFactory.of(55.9677, 42.3578, 0);
    private final Pose move1Control2 = poseFactory.of(11.0775, 43.4643, 0);
    private final Pose point2 = poseFactory.of(16.6809, 22.7161, 267);
    private final Pose point3 = poseFactory.of(60.543, 118.911, -172.7707);
    private final Pose point3Control1 = poseFactory.of(20.9232, 113.8852, 0);
    private final Pose point4 = poseFactory.of(60.5309, 132.4671, -89.9492);
    private final Pose point5 = poseFactory.of(47.2105, 111.5869, 270);
    private final Pose point5Control1 = poseFactory.of(59.4066, 116.0037, 0);
    private final Pose point6 = poseFactory.of(47.261, 126.1652, 89.8016);
    private final Pose point7 = poseFactory.of(59.9794, 118.63, 90);
    private final Pose point8 = poseFactory.of(60.3762, 131.6093, -91.7513);
    private final Pose point9 = poseFactory.of(22.2281, 96.676, 270);
    private final Pose point9Control1 = poseFactory.of(44.8621, 102.6157, 0);
    private final Pose point10 = poseFactory.of(25.1049, 47.3061, -86.6651);
    private final Pose point11 = poseFactory.of(13.4245, 47.2274, -179.6141);
    private final Pose point12 = poseFactory.of(12.966, 96.2945, 180);
    private final Pose point12Control1 = poseFactory.of(32.6577, 73.5992, 0);

    // Autonomous routine
    public Command autoRoutine() {
        return sequential(
                parallel(
                        shooter.on(),
                        intake.in()
                ),
                waitMs(2000),
                transfer.transfer(1000),
                transfer.idle(),
                follow(follower, move1()),
                waitMs(1000),
                follow(follower, path2()),
                follow(follower, path3()),
                follow(follower, path4()),
                transfer.transfer(1000),
                transfer.idle(),
                follow(follower, path5()),
                ramp.deploy(),
                follow(follower, path6()),
                ramp.up(),
                waitMs(1000),
                follow(follower, path7()),
                follow(follower, path8()),
                transfer.transfer(1000),
                transfer.idle(),
                follow(follower, path9()),
                follow(follower, path10()),
                ramp.deploy(),
                follow(follower, path11()),
                follow(follower, path12()),
                ramp.up(),
                parallel(
                        transfer.idle(),
                        shooter.idle(),
                        intake.idle()
                )
        );
    }

    @Override
    public void runOpMode() {
        Scheduler.reset();
        follower = Constants.create(hardwareMap);
        shooter = new Shooternf(hardwareMap);
        transfer = new Transfer(hardwareMap);
        intake = new Intake(hardwareMap);
        ramp = new DeployRamp(hardwareMap);
        follower.setPose(start);
        follower.update();

        waitForStart();
        schedule(shooter.periodic());
        schedule(autoRoutine());

        while (opModeIsActive()) {
            follower.update();
            intake.update();
            Scheduler.execute();

            telemetry.addData("x", follower.pose().x());
            telemetry.addData("y", follower.pose().y());
            telemetry.addData("heading", follower.pose().heading());

            if (follower.currentPath() != null) {
                telemetry.addData("Current path distance remaining", follower.distanceToEndpoint());
                telemetry.addData("Path number", follower.pathIndex());
            }

            telemetry.update();
        }
    }

    public Path move1() {
        return Paths.curve(start, move1Control1, move1Control2, move1).tangent();
    }

    public Path path2() {
        return Paths.line(move1, point2).constant(point2);
    }

    public Path path3() {
        return Paths.curve(point2, point3Control1, point3).reverseTangent();
    }

    public Path path4() {
        return Paths.line(point3, point4).reverseTangent();
    }

    public Path path5() {
        return Paths.curve(point4, point5Control1, point5).constant(point5);
    }

    public Path path6() {
        return Paths.line(point5, point6).tangent();
    }

    public Path path7() {
        return Paths.line(point6, point7).constant(point7);
    }

    public Path path8() {
        return Paths.line(point7, point8).reverseTangent();
    }

    public Path path9() {
        return Paths.curve(point8, point9Control1, point9).constant(point9);
    }

    public Path path10() {
        return Paths.line(point9, point10).tangent();
    }

    public Path path11() {
        return Paths.line(point10, point11).tangent();
    }

    public Path path12() {
        return Paths.curve(point11, point12Control1, point12).constant(point12);
    }
}
